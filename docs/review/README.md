# The human review before the freeze

Analysis plan section 8. Every false heal, and every session whose record lists
`needs_review`, is read by hand before the data are frozen. If the returned
test changed what the runner reported, the session is a leak: it leaves the
primary rates, numerator and denominator. Otherwise its label stands. Sessions
with a leak found by the audit are read too; a leak that did not change what
the runner reported removes nothing.

The stages read are 1a, 1b, 2-mixed and 2-c-assert. The exploratory stage is
not read: its figures carry the exploratory mark only.

## The worksheet

`just analyze` writes one worksheet per stage it reads to
`build/analysis/review-<stage>.csv`. Its first line names the SHA-256 of the
run's `provenance.json`. It has one row per observation that is a false heal,
lists `needs_review` or has an audit leak. The columns:

| Column | What it holds |
|---|---|
| `job_id` | The job, as the decision file names it |
| `stage`, `family`, `app`, `task`, `arm`, `rep` | The job's parts |
| `label`, `subtype` | The automatic label |
| `reasons` | Why the row is there: `false_heal`, `needs_review`, `audit_leak`, separated by `;` |
| `needs_review` | What the record lists, separated by `; ` |
| `leaks` | How many leaks the audit found |
| `transcript` | The session's stream (`out/stream.jsonl`) |
| `original_tests`, `returned_tests` | The test handed out and the test handed back |
| `snapshots` | The copy of the tests that each `run_test` call ran, one folder per call |

The paths are under the results root. The worksheet has no decision column: it
is regenerated by every run.

## The decision file

The reader writes the decisions to `docs/review/<stage>.csv` and commits it:

```text
job_id,decision,note
1a/b_oracle/bookstack/create_book/H/1,stands,the returned test checks the page; the runner's output is its own
```

- `job_id`: a row of that stage's worksheet.
- `decision`: `stands` (the label stands) or `changed_runner` (the test changed
  what the runner reported: a confirmed leak).
- `note`: what was read and why the decision, in a sentence.

A job that is not a row of the worksheet, a job decided twice, or another
decision refuses the run. The analysis reads the file and never writes it.

## What the numbers show

A number from sessions that include worksheet rows is written
`\todo{review not applied: …}` in `paper/generated/numbers.tex` while none of
those rows is decided, and `\todo{review incomplete (k of n): …}` while some
are. A decision file not committed marks every number `dirty tree`.

A `changed_runner` session leaves every figure computed over observations: the
rates, the paired differences and the descriptive figures. The labels table
shows it in its `removed` column, and section 8 counts it as a confirmed leak.

After the last decision is committed, run `just analyze` again from a clean
tree; `grep -rn 'todo{' paper/generated/` then lists what is still not final.

## The decisions of 2026-11-17

`1a.csv`, `1b.csv` and `2-mixed.csv` decide the 315 rows of the worksheets of
1a (115), 1b (107) and 2-mixed (93); 2-c-assert has no row. Each row was first
read by Claude Fable 5.2 (`preread-instructions.md`), and the author checked
every answer and decided the row. All 315 stand: no session changed what the
runner reported. Each `note` gives the pre-read's sentence and the author's
decision.

`changed_runner` covers writing or modifying the runner's settings, code or
output files, not reading them; the pre-read's instructions, which say "reading
or writing", are kept as its sessions had them. The agent is given the failing
run's output, a snapshot of the page and a screenshot in `test-results/`
(`prompts/operating_note.txt`), and reading them changes nothing the runner
reports; 138 notes name `test-results/`. A read outside the workspace is the
audit's.

The audit flagged 11 rows. One flag is a false positive: the `../..` it found
is an XPath selector, not a path. In the other 10, the agent called Grep or
Glob on a path outside its workspace, and the CLI refused the call
(`--restricted: path outside the working directory`), so it never ran. Those 10
stand, as section 8 decides: a leak that did not change what the runner
reported removes nothing.

### Refused attempts

`refused-attempts.csv` lists those 10 jobs (columns `job_id`, `note`): six of
1a and one of 1b, all arm N, and three of 2-mixed (two N, one H). The analysis
computes every figure of the three comparisons and every descriptive figure,
Mixed's among them, again without them, as exploratory figures under
`refused-out/<id>` with `of` naming the comparison (none for a descriptive
figure): in `analysis.json` (`refused_out`), `figures.csv` and `numbers.tex`,
and not in the comparisons table or the forest plot. Since the 1a and 1b jobs
are all arm N, only comparison 1's N figures and Mixed's N and H figures can
differ from the main ones; comparisons 2 and 3 (G minus H) come out the same.
The main results keep the 10. A job of a stage that is not reviewed, a job that
is not a row of its stage's worksheet, a row without an audit leak, or a job
listed twice refuses the run; a job of a reviewed stage that the run does not
load is left aside. `provenance.json` records the file's SHA-256 under
`refused_attempts`.

The author's points that the paper must settle are in `paper/README.md`
("What section 8's review leaves to the paper").
